# QA and corrections — planned

Status: requirements and open questions; no operational QA module is available for training.

The owner envisages supervisors reviewing mobile-submitted transactions mainly on web and recording QA pass or fail. Submitted evidence is used for payment, salaries and invoices, so historical submissions must remain trustworthy. Field errors still need a controlled correction route.

A possible approach is to keep the original immutable and create a linked correction submission with the reason, actor and review history. This is a proposal, not an approved design. The effective operational record, meter-number uniqueness, duplicate-safe retries, approval flow, repeated failures and financial adjustments remain unresolved.

Do not teach users to edit an original transaction, bypass duplicate protection or repeat a meter discovery as a correction workaround. Report the transaction/meter reference and error through the currently agreed support process while the module is designed.

See [DEC-008 and DEC-009](../../00-academy-governance/OWNER_DECISIONS.md). Future QA lessons must explicitly cover both reviewer and fieldworker responsibilities and preserve the distinction between original evidence and approved corrections.
