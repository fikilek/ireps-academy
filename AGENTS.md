# Academy contributor instructions

Read [the charter](00-academy-governance/ACADEMY_CHARTER.md), [owner decisions](00-academy-governance/OWNER_DECISIONS.md) and [contribution process](00-academy-governance/CONTRIBUTING.md) before changing Academy content. Follow the owner's current instructions when they override an inherited document.

- This Academy Codex workstream owns training content and the master dictionary.
- Use **Super User** for SPU; exclude Guest from the active role catalogue.
- Do not settle permission inheritance, offline retry/deletion, QA correction/payment rules or Trials by inference.
- Separate observed source code, accepted product direction, deployed behaviour and published training.
- Preserve source provenance and existing user changes. Do not overwrite another agent's development worktree or modify Firebase data to verify a lesson.
- Keep historical assessments outside learner navigation. Import once and link to the canonical Academy document.
- Check links, content status and applicable release before publishing. A request to organise and back up documentation does not authorise an application deployment.
